## 愿望与四个方向

让第一次听说项目的人、只知道名字的实验室同伴、几个月后的自己，能够理解：研究问题为什么值得做；方法改变了什么；结果真正说明什么；依据在哪里；下一步怎样减少不确定性。

A 开发：减少维护和验收成本，不追逐框架版本。B 内容：组织读者理解，不转储实验日志。C 设计：让关系、对比、流程可见，不增加装饰。D 证据与研究决策：把零散材料变成可复核分析、竞争解释和可检验的下一步。

第四方向不是再建一个管理平台。先用现有仓库、版本化 JSON、纯函数和原有页面；不引入数据库、后台服务、通用知识图谱或自动科研 Agent 平台。

## 科学与表达的共同底线

1. 显式区分 observed（观测）、derived（按代码计算）、inferred（解释）、proposed（待验证）。未运行、运行失败、数据缺失、零分分别表示。
2. 分数必须有任务集、评估角色、分母、单位、时间窗口、聚合方式和来源。训练曲线回升不是新的冻结 Final；32/64/128-task 不混成一个绝对分数排行榜。
3. 对照中什么固定、什么作为处理变量变化，须由比较合同声明。单条历史曲线、相关性和少量种子不能被写成普遍因果结论。
4. 发现新解释不等于强求另类结论。别人也得到同样的正确答案不是失败；本项目增值在于排除替代解释、识别哪些比较无效、量化取舍并提出能区分解释的实验。
5. ELI5 降低背景门槛而非删除专业深度。正文先说对象和关键事实；公式、代码、来源按需深入。影响结论的限制不能藏在 details、鼠标悬停或登录墙后。
