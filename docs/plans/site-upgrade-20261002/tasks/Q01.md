# Q01 · 全站覆盖、独立冷读与最终整合验收

状态：计划已编写，尚未实施。工作量：M：覆盖与整合验收，不再重做各条实现。依赖：A01, A02, A03, B01, B02, B03, C01, C02, C03, D01, D02, D03, D04, X783, X805, X806, X812。

共同边界：[COMMON](https://github.com/mykcs/basemodel/blob/docs/site-upgrade-program-20261002/docs/plans/site-upgrade-20261002/COMMON.md)。当前会话只授权计划与 Draft PR，不授权运行本文件中的实施步骤。

## 目标

验证网站是否真的更容易理解，而不只是实现了更多组件。每个页面家族有去向，每项完成有对应证据，不能用一个总百分比掩盖缺少冷读/生产确认。

## 已有 owner

`src/data/siteReaderContracts.ts`、`scripts/audit-reader-contracts.ts`、`tests/e2e/site-reader-contracts.spec.ts`、现有全站 UI/静态优先/数学/图表/导航测试与 X806 路由清单。

本规划附 ROUTE_SOURCE_INVENTORY.json 是调查时的源码清单，不是实际构建路线或通过证据。执行时用真实构建生成路由，与当前 Reader Contracts 对账。

## 代码与验收步骤

1. 给所有实际公开 route family 标处理 owner：入口/Study→B01；研究正文→B02/X805/X812/X806；复现/历史→B03/X806；机制→C03/X806；Models/Papers/Compare/Workspace→X783/X806；Landscape/性能→A02/X806；Development/全局/404→X806及相关开发 owner。redirect/API/归档源分别标记，不当新页面漏测。
2. 以各 PR 的真实更改范围合成影响图，补遗漏和冲突，不能默认“示例页漂亮所以全站完成”。共享 CSS/schema/navigation 的冲突只由指定总控整合，禁止多名 Agent 同时改同一 owner。
3. 对一个来源变更走完整纵向切片：批准快照→比较分析→图/表/句子→导航/历史→证据追溯。检查同一数值在三处一致、错误输入失败关闭、未知不变0。
4. 独立冷读覆盖新读者/实验室同伴/回访者三个角色。准备不透露答案的任务：说清问题、主要结果、限制、下一步、找到依据。建议每个角色至少一名真实读者；匿名记录任务/答案/阻点，不收不必要个人数据。
5. 候选冷读接受线：五问至少四问正确，且不能误读训练与 Final、跨面板比较或“未做=零”；对照旧版与新版的任务完成路径/用时/错误，顺序平衡。小样本作为发现问题的质量验收，不称统计显著。若无真人，标 reader_evaluation_pending，Agent 冷读单列，不能冒充 owner 已认可。
6. 按现有 gate 运行最终当前-base/head deterministic/build/适用全量 UI，保留手机/桌面、亮暗、键盘、无 JS、减少动画、缩放、打印证据。未覆盖项不写 PASS。
7. 在用户明确授权发布后才请求 persistent Vercel final gate，由一个整合 head 发布并单独验证 Production。普通规划/实现 pushes 不触发 Vercel；READY、合并、在线产品接受分别报告。

## 交付

全站覆盖矩阵（每条有 owner 与证据/不适用理由）、纵向数据一致性用例、冷读材料和结果、剩余问题分级、唯一整合候选及回退指针。状态分为计划完成/技术完成/独立阅读验收/owner 接受/生产验证，不能折叠。

缺陷只有回到已有 owner 修复，不能在 Q01 大规模重写文章或新加一套设计体系。新发现超范围问题有明确归属和计划，重大遗漏阻止“全站完成”。

## 负例与停止

同一结果图/表/句子不同；通过缩小首屏 selector 或增加空白作弊；动画可见但无数据流；缺任何页面家族；缺真人但声称可读性提升已证实；旧 SHA CI 冒充新候选；匿名被访问保护拦截却报告 Production 坏了。

来源或科学边界有冲突，暂停该发布候选并修 owner；不放宽 gate。回退到已验收网站版本，原始研究证据和历史不删除。本规划不合并/不部署。
