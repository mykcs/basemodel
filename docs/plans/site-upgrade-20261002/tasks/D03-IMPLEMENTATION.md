## 三项分析及结论边界

### 学习信号

使用 #805 固定版本中的三个训练 epoch 和同一64题验证面板。训练 loss 从报告的2.713降到0.830，按这两个报告数值算约下降69.4%。三个 epoch 的验证任务分数均没有高于初始状态，后两个 epoch 的正奖励任务数为0。

实现保留所有三个 epoch，不挑选最好一次；计算各状态相对初始状态的均值差，并核对报告的差值。来源中的区间被完整保留，标记为 `source-reported-not-recomputed`；没有拿四个汇总数字生成新的显著性或相关性检验。

这说明该次 Stage1 学习目标的优化没有带来对应的留出任务能力改善。它不证明完整 SEED Stage2 无效，也不能把第一个 epoch 的区间跨零解释为等价。SFT 验证 loss 和 WebShop 任务表现使用不同对象与量纲，不能混成同一条“验证分数”。

### rank32 容量

覆盖报告的第152–159轮全部1024次配对尝试，核对均值、完整成功数和 adapter 字节数。由已有汇总计算：

- adapter 体积减少约74.99%，节省154,141,232字节；
- 平均 Task Score 下降约1.79分，按0–100显示；
- 完整成功数增加9次，相当于约0.879个百分点。

两个行为指标方向不同，必须分别解释。1024次 rollout 不被填成1024个独立样本；独立任务/配对身份未重新读取，保持未知。报告的区间不重算，不指定事后的非劣性容许差异，不写成无损、等价或 rank8 足够。

均值相减可能和来源直接报告的差值有机器浮点末位差异；实现把“按报告均值复算值”和“来源报告值”同时保留，并按明确容差核对，不覆盖历史值或声称多出的末位是额外测量精度。

### β 后期训练

使用 D02 已固定的第96–199轮104行标量，复算原先五个窗口的 Task Score 均值、loss 均值、线性斜率和完整成功数。首个窗口有24轮，后四个窗口各20轮；不得把它们当作相同数量的原始样本。

| 轮次 | 轮数 | 平均 Task Score（0–100） | 完整成功数 |
|---|---:|---:|---:|
| 第96–119轮 | 24 | 59.36 | 688 |
| 第120–139轮 | 20 | 61.58 | 619 |
| 第140–159轮 | 20 | 54.28 | 675 |
| 第160–179轮 | 20 | 59.51 | 700 |
| 第180–199轮 | 20 | 60.39 | 852 |

全部窗口参与，没有事后挑最好窗口。loss 的窗口均值持续下降，但 Task Score 从第120–139轮到第140–159轮下降，此后两个窗口又回升。数据不支持把 loss 单独当作停止轮数的依据，也不能据此判定120、160或200轮最优。

冻结 Final 仍是历史已发布的60.72、45.98、20.77分；训练回升不产生新的 Final。没有尝试把训练窗口和最终评估组成一个合法差值。β 强度、方向或状态变化的机制解释继续交 D04，不由相关变化自动生成因果结论。

## 可比性与反例

明确不同任务集、32/64/128题混比、不同评估角色或指标单位会被拒绝。未提供的 harness、解码、预算、检查点或配对身份会产生可读原因，并限制为描述性比较；不会为了填满表格猜测身份。

模型可以是合法处理变量，不要求两个模型名称必须相同；同一字段不能同时声称固定和变化。需要原始配对重算时，缺记录、重复配对、重复独立单位、错误分母都失败。这里没有建立一套新 bootstrap 代替上游统计方法。

窗口必须覆盖整个已声明范围；缺测保留，不补零、不插值。缺数据时完整窗口估计为未知，观测部分均值单独标记。已有汇总与重算不一致时检查失败。成功计数要求严格相等，浮点重算使用明确容差。

## 正常使用与复现

```bash
# 默认不联网；三项状态与 β 已发布范围复算
npm exec -- tsx scripts/research/analyze-evidence.ts

# 校验已提交生成文件；正常 npm run validate 已包含此检查
npm exec -- tsx scripts/research/analyze-evidence.ts --check

# 固定代码/资料变化后，重新生成已有发布范围的快照
npm exec -- tsx scripts/research/analyze-evidence.ts --write-projection

# 已在受限 reports 目录放入 #805 固定来源后，分析全部三个问题
npm exec -- tsx scripts/research/analyze-evidence.ts \
  --post-advisor reports/research-analysis-inputs/post-advisor-ab-final-20260928.json \
  --write-report

# 第二实现核对当前提交的 β 与冻结 Final 算术
python3 scripts/research/verify-analysis-independent.py
```

#805 的输入固定为 `mykcs/basemodel@43fa2cbb3998824333826e8542cebf8265842f17` 中的 `public/research/seed-openevo/evidence/post-advisor-ab-final-20260928.json`。SHA-256 在 `ANALYSIS_SOURCES` 中固定；本轮通过已授权 GitHub 只读获取到本地被忽略的 `reports`，未复制进 src/public 或改变来源 PR。

受限分析输出位于 `reports/research-analysis/<内容哈希>.json`。第二实现可用 `--report <此相对路径> --post-advisor <输入相对路径>` 核对三个问题。重复执行得到同一内容哈希；输出无采集时钟噪声，来源、代码、选择和结果身份都能追溯。受限输出被禁止写入网站快照。
