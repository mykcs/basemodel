# Q01 首批验收交付

## 本批完成范围

本批把“全站有没有被漏掉”变成构建时真实执行的检查，并记录尚未完成的最终整合与真人验收。没有修改网页正文、样式、实验结果、CI 工作流或依赖版本；没有合并、请求 Vercel 或发布。

`astro.config.mjs` 接入一个窄的构建检查，使用 Astro 实际解析的路由及实际生成的输出，不复制动态模型/论文目录，也不把源码文件数当网页数。所有完整构建都会执行；开发服务器不运行这一验收。

## 实际覆盖

在本次基线上：84 个页面相关源码文件中，68 个是公开页面模式、10 个是复用片段、6 个是数据接口模式。构建后得到 262 个内容页面、3 个兼容跳转页面，以及 172 个数据接口输出。归档的 62 个英文页面源码没有算进当前可访问网页。

265 个 HTML 页面都绑定了已有 Reader Contract 与升级任务；模型、论文、比较、工作区、复现指南、历史页和机制页没有因当前研究主题突出而被漏掉。静态资产不当作网页；Astro 内部、不预渲染的图片服务也与本次静态输出分开记录。

这证明的是路由归属完整，不是这些页面都已经改版或通过真人阅读。构建报告明确把视觉、真人理解、用户认可与生产发布留作未验收。

## 文件与命令

- `scripts/site-acceptance-build.ts`：构建钩子；检查生成清单、真实输出和材料指纹。
- `scripts/site-acceptance-core.ts`：复用 Reader Contracts，绑定任务，拒绝空输出、无来源、缺少页面族、缺失跳转目标、未分类接口和重复路径。
- `scripts/site-acceptance-files.ts`：原始文件哈希、输入指纹和源码/归档分类。
- `scripts/audit-site-acceptance.ts`：重新核对已有构建，拒绝旧产物、篡改、增删文件或冒称已完成人工验收。
- `scripts/site-reader-evaluation.ts`：检验真实读者记录，不把 Agent 试读充当真人。

在候选仓库内运行 `npm run build`，报告写入 Git 忽略的 `reports/site-acceptance/coverage.json`，不会发布到网站。然后运行 `npm exec -- tsx scripts/audit-site-acceptance.ts` 验证输入和输出仍然相同。材料变化或构建失败之后，不得复用旧报告。

输入指纹的范围写在报告里；它补充而不取代 A01 的 CI 产物身份、完整提交身份及 Vercel 最终检查。当前本地验证属于未提交工作树预检查，最终提交的云端结果另记在 PR 中。提交变化也会使旧报告失效，即使网页材料恰好相同。

## 依赖与整合风险

[依赖快照](Q01-DEPENDENCIES.json) 重新读取 17 个相关 PR 的实际 head、base、完整文件列表和独立 Public PR CI。C01 已有真实 PR 827，不能继续沿用早先“PR 尚未创建”的状态。

本 Q01 检查分支没有包含这些实现分支，17 个依赖 head 的祖先检查均为未包含。它们之间有 36 个重复改动路径：其中 20 个路径各参与者的文件内容相同，16 个路径存在不同文件状态。相同文件通常来自堆叠依赖；不同文件状态需要审阅，不等于已经证明 Git 合并冲突。

整合时应按真实职责处理：

- `OpenEvoEffectiveStateGdrLoraStudy.astro` 同时涉及 C01 表格、C02 图表与 X806 样式。表格导出和图表必须接同一个科学数值来源，不能通过整文件覆盖丢掉其中一项。
- X805、B02、C01 已带结果投影；D01/D03/C02 中的待接入状态需要在唯一候选中一并核对。不能让一个页面显示结果，另一个页面仍显示同一结果“未接入”。
- `siteReaderContracts.ts`、研究目录、模型比较和全局样式由 B01/A02/A03/X806 等分别改变；只保留各自仍有效的改动，不批量选 ours/theirs。
- `validate-data.ts` 及 CI 测试存在多个版本。必须保留 D01/D03/B03 的校验职责以及 A01 的精确产物边界；各 PR 的绿灯不转移到合成后的候选。

本批只检查、记录和建立保护，不自行关闭别人的 PR、不改科学语义。完整文件级清单与 blob 身份均在依赖快照中。

## 对照构建的边界

用同一锁文件分别构建 main 与本批候选，双方各产生 630 个文件。199 个 HTML 文件的原始字节不同；差异全部局限于 Astro island 的 uid 属性。只在对照诊断中归一化该属性后，其余字节一致。原始产物检查仍使用完整字节哈希，没有忽略 uid，也没有借用另一个构建的收据。

同时修复了验收器自身一个错误：结构解析改变对象字段顺序会造成清单哈希误报。现在按明确排序的字段元组计算清单身份，并加入属性顺序变化与真实字节变化的反例测试。

依赖快照可以用 `python3 scripts/snapshot-site-upgrade-dependencies.py` 重新生成；需要已授权的 GitHub CLI，只读取 GitHub，并将指定提交取到本地供祖先检查，不写远端。发生 head 变化会停止，避免把两个版本的文件列表拼成一个结果。脚本对瞬时 GitHub CLI 失败最多重试两次后仍失败关闭；2026-10-03 的刷新实际遇到一次 TLS handshake timeout，第二次读取成功，没有把部分结果写成完整快照。刷新同时发现 C01 / #827 从 `37cc61c…` 前进到 `94ac62c…`，因此旧依赖快照作废并重新生成；17 项依赖仍有 36 个重叠路径，其中 16 个需要 owner 对账。
