# 阅读验收主持说明

参与者只收到 [阅读任务单](Q01-READER-TASKS.md)，不要同时发送本文件或带结论的 PR 正文。

## 尚未开始

本次没有真实读者参加。真人试读数为 0，状态为 `reader_evaluation_pending`。自动化单测里的回答全部是合成测试数据，不能当研究结果。旧网站与最终整合候选尚未完成配对，不填写虚假的版本、回答或时间。

## 版本与参与者

先确定实际被改变的阅读表面，固定基线与候选的代码/构建身份，分别保留其输入指纹。三类读者至少各一位；使用随机的 `reader-...` 匿名编号。按基线先读、候选先读两种顺序平衡分配，总人数的两种顺序之差不超过 1。不能只挑最容易理解的一篇文章代替全站路径。

记录参与者亲自给出的五个回答、所用时间和访问路径。主持人按冻结证据逐问评分，不凭答案是否符合自己的研究故事打分。确认结果确实来自真实读者后，才填写 `stewardVerified=true`；该字段本身不能证明人的身份。

## 接受线

候选版本五问至少四问正确，而且不得把训练曲线误读为最终评估、把不同题集当配对实验，或把未知/未做当零。错误问题回到负责该页面的既有 PR；不为获得通过而降低标准。

`evaluateReadingTrials` 在 `scripts/site-reader-evaluation.ts` 中实现以上检查：空结果、只有 Agent、缺少某类真人或顺序不平衡都保持待验收；关键科学边界误读会失败；旧版或旧候选的结果不能移借。原始回答与评分应另存经过匿名化的 Markdown 记录，填写 `resultRecord` 和文件哈希。

## 证据等级

Agent 阅读只记录为 Agent 阅读。真人小样本完成表示这一轮质量检查完成，不证明统计显著改善，也不自动表示用户认可或生产发布通过。主持人还应逐版本比较用时、错误和访问路径；不能只保留候选得分较高的样本。

真人验收、用户认可、Vercel 最终检查及实际生产验证分别收集。当前 Q01 没有请求发布，不会因加入本工具就自动启动这些动作。

比较前确认两版的科学材料范围。评估排版或导航时尽量保持材料相同；两版同时改变了研究内容时，应把内容增加与表达改变分别记录，不能将理解差异全部归因于设计。
