# C03 · 能看出数据怎样流动的原生 HTML 机制图

状态：计划已编写，尚未实施。工作量：M：Vanilla SD-LoRA 一轮及其可复用小能力。依赖：无实现依赖，可先行。

共同边界：[COMMON](https://github.com/mykcs/basemodel/blob/docs/site-upgrade-program-20261002/docs/plans/site-upgrade-20261002/COMMON.md)。当前会话只授权计划与 Draft PR，不授权运行本文件中的实施步骤。

## 目标

零背景读者看得出谁输入什么、哪里训练、什么保留、什么变化、失败时怎样走，而不是看到一排静止卡片。HTML 的优势是分层、联动、可访问与可验证关系，不是自动动画。

## 已有 owner

`src/data/vanillaSdLoraMechanism.ts`、`OpenEvoVanillaSdLoraMechanism.astro`、`OpenEvoVanillaSdLoraSlide.astro`、已有 MathFormula 和 mechanism/flow 浏览器 tests。复用固定的 round/selection/trainer/state 数据及其 pinned upstream sources。

先检查当前图、step controls 和状态逻辑；存在的能力修其真实不足，不再建立另一套 slide engine。新 `MechanismStep` 类型或小组件仅在同义实现不存在时引入。

## 实施步骤

1. 从固定源码核对一轮的真实分支：训练任务 rollout→筛选每题最早合格完整成功→当前与有限旧经验→训练新方向及系数→生成累计候选→按所属实验的应用规则→下一轮。没有可用数据时的真实 no-update 路径也要画；不得编造 GDR 恒存在。
2. 用原生 ol/section/稳定 anchor 表达顺序；CSS Grid/SVG 连线显示输入、输出、回路、条件。连线带语义标签，不能只靠箭头/颜色暗示因果。
3. 把“冻结 base”“冻结旧方向 D”“仍可训练的 α”“新增 D”区分清楚，公式与相应节点就地联动。普通 LoRA 与本项目适配区别保留，bounded replay 与原论文 rehearsal-free 的差别不得隐藏。
4. 小交互采用显式状态 `activeStepId`；点击/键盘后突出相关节点、数据例子与公式，其他内容仍可找到。默认不自动播放；若有播放，明确暂停/重播且尊重 reduced-motion。
5. 无 JS 时展示完整有序流程和分支；手机顺序和桌面相同，长公式局部滚动，focus 不丢，图的 SVG IDs 按实例隔离。
6. 演示数字取已有 facts；需要示意样本明确标“示意”，不能冒充真实轨迹。最终评估任务没有进入训练、筛选或动画数据流。
7. 在机制页先实用，slide 只复用稳定的数据/图形，不复制逻辑。读者离开图后能回答下一步去哪，不被固定悬浮控件从首屏抢走注意力。

复用 vanillaSdLoraMechanism/plainLanguage tests，新增步骤边/状态合法性、缺入口、孤立节点、循环停止条件、重复 SVG id、键盘与 reduced-motion 测试。核对 390/768/1440、亮暗、200% 放大、打印，不用全页面截图代替节点数据正确性。

## 排除/回退

不修改训练协议、公式含义、TaskMem/Skill/Agent 行为，不创建无证据因果流。不做3D场景/装饰动效。交互失败回退原生有序流程，不隐藏内容；与 X806 样式冲突在 scoped owner 解决，不改全站 CSS。
