## 使用

在仓库根目录、Node 24 与既有锁文件依赖就绪后：

```bash
# 默认只读验证，不建立输出目录
npm exec -- tsx scripts/research/import-history.ts --all

# 单个明确允许的来源
npm exec -- tsx scripts/research/import-history.ts beta-r200

# 显式写入本地 reports；不进入 public、不上传、不改源文件
npm exec -- tsx scripts/research/import-history.ts --all --write
```

输出位置为已被 Git 忽略的 `reports/research-history/<内容哈希>.json`。相同科学内容重复导入会核验并复用原文件；实际导入时间保存在外层记录中，不参与科学内容哈希。源观察时间与续跑的原始步号仍保留在来源记录中。

先写临时文件，再以不覆盖的方式提交完整文件。中断不会留下貌似完整的结果；已有文件有不同内容、损坏或被软链接替代时直接失败，不能覆盖掩盖问题。这里实现的是固定离线资料的安全重试，不是网络下载断点续传。

## W&B 后续接入

官方 [Run API 文档](https://docs.wandb.ai/models/ref/python/public-api/run) 区分抽样 `history()` 与完整历史读取 `scan_history()`；后续在线来源必须核对实际锁定 SDK 的行为，并验证源仍在变化、分页中断和字段异步记录。不能仅因为声明了 `complete-export` 就信任未经核验的导出：目前 CLI 只接受这里三个已固定哈希的来源，其他来源需要新增经过审阅的映射。

在线接入还需把真实 run/continuation 身份、源导出版本、数据范围及许可传入本接口；保持每指标流的并集和缺失记录，不把多字段交集当完整历史。禁止在网站构建时调用在线服务，禁止让实验服务器保存新发布凭据。

D03 可读取规范化快照和来源记录；C02 可消费同一组点。新的来源接入、统计比较、图表发布和正文综合仍由各自 PR 完成，不能仅因导入成功就宣布科学结论成立。
