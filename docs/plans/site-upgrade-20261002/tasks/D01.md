type EvidenceSnapshot = {

这是拟议接口，不是已存在代码。模型、任务流、seed、训练预算、harness/解码、checkpoint lineage 等放在被引用的比较/实验合同中，不重复塞每行，也不能丢失。

## 代码步骤

1. 清点三种代表：冻结 Final、长训练曲线、rank32 对照。记录当前数字在哪些 TS/JSON/正文重复，哪些是 raw/derived/显示值；先承认来源缺失，不补猜。
2. 建 schema 和 source refs，区分实验状态、证据完整度、publication 许可。未知不能默认0、未批准不能默认为可公开；非秘密也不自动等于可公开。
3. 在可信控制端验证源文件哈希、字段和许可；生成构建可读的净化快照。前端/CI 不能持有服务器凭据或在 build 时查实时 W&B。
4. 给既有发布 TS 数据做兼容适配：保持读者可用的旧地址/标识，逐调用方迁至单一数据源，迁完才删除旧常量。已有冻结结果不被新 schema 重算或改写。
5. 将 table/chart/prose view model 统一从同一 snapshot ID 取值；source 变更时列出依赖消费者交 B03，不自己建立第二套 freshness 后台。
6. 只发布必要聚合/白名单字段；原始轨迹、checkpoint、私有 host/IP/用户名、临时 share 参数不进 public 或 PR 正文。源文件缺批准时保持 restricted/blocked，不能为了页面完整公开。

## 交付与验收

三个代表来源接入，字段来源与兼容迁移表、schema 单测、净化结果、旧/新数值一致性检查。每个代表表/图/关键句可定位证据 ID，哈希不符阻止发布。用已有 validate/audit 入口接入，不重复建立整个验证框架。

负例：重复 id、错 hash、无比较合同、训练冒充 Final、未知样本量变0、字段单位变化、未批准发布、secret-like/private 地址、不可解析 revision、只存在 display rounded 值。缺 raw 数字只保留报告精度，不创造更多小数位。

## 停止与回退

D01 是研究 schema 唯一 writer；下游通过契约 fixture 协作。缺来源/权限只隔离该证据，不让整个静态网站依赖实时服务。回退消费适配但保留原证据与链接；不迁移仓库可见性、不访问冻结评估题。
