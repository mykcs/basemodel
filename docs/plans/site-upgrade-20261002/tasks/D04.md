## 必须覆盖的五个问题

1. loss 下降/held-out 未升：目标学习到但信号迁移不足，与格式/分布差异等解释如何区分？不能直接结论“方法无效”。
2. rank32 体积更小但指标取舍：容量瓶颈与训练信号瓶颈如何区分？低 effective rank 的事后诊断不直接证明最小可训 rank。
3. β 后期训练回升但冻结 Final 较差：短期门控、训练分布改变、遗忘与评估差异哪些还可能解释？训练回升不是自动授权再测 Final。
4. 120/160/200 轮是否值得：至少跨相关方法与同预算视角审查；一个 ordinary OpenEVO 的平台不能推广到全部方法。轮次收益和墙钟/GPU成本都要看，停止结论需考虑随机波动。
5. 加速之后预算怎么重新分配：更多种子/任务覆盖/诊断与更长单次训练的机会成本是什么？2.01× 等价路径与37.04× 改表征历史不是同一科学保证，重用前先核其真实合同和时间范围。

这些是研究问题与候选解释，不是本计划新发现的实证结论。

## 执行步骤与交付字段

1. 为每个问题建立一页以内证据矩阵：已知观测、支持解释、冲突证据、仍有可能的替代解释、当前无法辨认的原因。
2. 为每个候选实验写竞争预测：若 H1 真更可能看到什么、若 H2 真更可能看到什么、什么结果两者都解释得通。没有区分力的实验不优先。
3. 写清对照臂、固定项、处理变量、数据/seed、首要指标、独立单位、分析配方、成功/否证/停止条件；缺少授权或预算的字段明确待批准，不自动补成已承诺训练。
4. 计算预算使用可审核公式：模型/臂数×seed×轮次×每轮rollout，以及来自真实测量的训练/推理耗时和存储估计。未知给区间或未知，不造一个精确 GPU 小时数。
5. 按“是否会改变下一阶段选择、现有证据强度、成本、可区分性”给有理由的顺序与敏感性；不制造没有意义的统一价值分数。
6. 将结论分为继续/停止/保留/等待数据，给出会改变它的证据；关联上游既有 PR。B01/B02 消费这个小数据，读者能从判断返回证据。

```ts
// 提议；状态永远不隐含运行授权。
type DecisionNote = {
  questionId: string; evidenceIds: string[];
  hypotheses: { id: string; supports: string[]; conflicts: string[] }[];
  nextStudy: { existingPr?: string; discriminatingPrediction: string;
    budgetStatus: 'unapproved' | 'approved'; stopRule: string };
  status: 'inference' | 'proposal' | 'adopted_with_evidence';
};
```

## 验收与反例

五个问题都有真实证据或明确缺口、至少两个可区分解释（单一解释足够时给依据）、下一动作、代价、停止规则和权限状态。不能只有“多跑几个实验”。每个建议至少能指出哪项项目决策会因结果改变。

反例：只拿一个方法判断训练轮数、低 rank 直接推最小容量、训练曲线充当 Final、相关性当因果、H1/H2 所有结果都能解释、先看数据再写成预注册、给未批准实验标进行中。测试 schema/状态与链接，独立研究审阅保留 dissent，不为了整齐压平不确定性。
