# D02 · 服务器与 W&B 历史数据的只读接入

状态：计划已编写，尚未实施。工作量：M：三个已存在实验的可恢复导入，不训练。依赖：D01。

共同边界：[COMMON](https://github.com/mykcs/basemodel/blob/docs/site-upgrade-program-20261002/docs/plans/site-upgrade-20261002/COMMON.md)。当前会话只授权计划与 Draft PR，不授权运行本文件中的实施步骤。

## 目标

使零散日志/已有 W&B history 进入同一可追溯快照，避免为了画图重跑实验，或从抽样面板误读完整趋势。此任务实施范围是 BaseModel 消费端/可信控制端的读取与导入，不修改训练器或源实验。

## 已有/拟新增

现有 `public/research/seed-openevo/evidence/wandb-threeway/receipt.json`、JSON/SVG、q17-wandb-lineage-audit，以及上游实验仓库已有批准导出脚本/产物。

拟新增 `scripts/research/import-history.py`、小型版本锁定 Python 环境/测试、输入来源清单，或复用已找到的等价 importer。代码运行在现有授权控制端，数据来自用户资产允许清单；新凭据不落共享计算机。

## 接入过程

1. 先查上游现有导出 owner，列 run/continuation/checkpoint 身份和已批准数据位置。选择三个代表：同一 run 正常 history、有 resume 的曲线、局部缺字段/失败的记录。只读小清单和标量，不复制大 checkpoint、不全盘扫描他人资产。
2. 明确 metric 单位、x 轴是环境轮次/optimizer step/墙钟，metric 是否同步记录。不要把一个 run 的 step 与另一个 run 的 step 直接拼起来。
3. 核对所固定 W&B SDK 的 `history` 抽样与 `scan_history` 语义。分析使用可证明完整的分页/原始导出；异步记录指标不能用要求多 key 同时存在的查询悄悄取交集。按各指标流读取并显式 join，缺值保留 null。
4. 以 run lineage、metric、原始 step/time 标识去重；冲突值单独报告，不 last-write-wins。记录页数、行数、时间/step 范围、重试、源版本、导出 hash 和 incomplete 标识。采集中的来源先冻结快照，不能边变边称完整。
5. 生成 D01 净化输入，经允许字段/发布许可验证后再进入网站。失败可幂等重试并恢复，不截半文件当完成。默认命令 dry-run，不改源数据。
6. 需要在 W&B 展示旧散数据时，仅在后续获得对应写入授权后创建明确标识的派生分析 run/report，保留源 ID、原始时间和导入时间；不重写原 run、不伪装实时训练、不改变任何公开设置。
7. W&B 不可达时可以消费已批准本地导出并显示来源范围；不能称账号权限已丢失或自动重新登录/复制 token。服务器只读路线遵守当前 host/project policy。

```text
approved source list -> read-only export -> completeness/lineage checks
 -> normalized metrics + receipt -> D01 publication check
 -> D03 analysis -> C02 static/interactive figures
```

## 交付与验收

交付 importer、来源映射、三种 fixture 的 receipts、幂等恢复说明、净化产物。重复导入同源同版本得到相同 normalized 内容/hash（采集时间不纳入科学内容 hash）；源行数和缺失比例可复核。

反例：抽样 history、异步 key 丢行、resume 重复 step、不同 run 冲突、分页中断、来源仍在变、未知单位、permission denied、credential-like 字段。测试用脱敏 fixture；可用真实已批准数据只读验证，不训练、不访问 Final 题目、不删除文件。

## 停止/回退

若需修改上游 instrumentation 才有某指标，本任务登记缺测及上游已有工作项，不在网站 PR 偷改科学执行；本计划不创建空壳“全指标平台”。撤销导入投影保留原数据和 receipt，旧网站快照仍可用。
