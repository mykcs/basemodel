## 实施步骤

1. 比较 docs-only、局部 UI、全局 UI 三类合法计划，拆出 install/build/browser/等待/总 runner 秒/关键路径。优先复用近期同版本日志；缺证据再补有界资格，不刷无意义 hosted run。保持当前分片数和覆盖，不同时调并行度。
2. 从 lockfile 确认实际工具身份，核对官方镜像并统一 Playwright 安装路线。只有镜像匹配、所需浏览器可用时才省下载，不以 package 范围版本充当实际版本。
3. deterministic 成功构建后产出清单，绑定 head/base、lockfile、Node/npm、构建输入、site/locale、文件列表及内容哈希，再上传静态产物。环境字段采用允许清单，不把全部 env 写进文件。
4. browser 使用明确的数据依赖，下载本次 workflow 的同一提交产物，验证成功才设 CI_BROWSER_BUILD=0。不跨 PR、不取“最新成功”，不用带额外权限的 workflow_run 执行不受信 PR。测试依赖仍按需安装。
5. artifact 平台的 digest 不匹配可能只报警，本仓校验器必须主动失败。缺失/损坏/身份漂移不得降成 PASS，也不得拿旧 artifact 静默顶替。
6. 保留 public-ci-gate 的失败关闭，docs-only 仍有适用检查。Vercel 继续独立构建最终候选，GitHub artifact 不能代替 provider build。
7. 比较旧/新三类变更的总消耗和关键路径；若下载与等待抵消收益，保留原路线并交付有证据的“不采用”，不能为预设提速率放宽检查。

## 交付与验收

交付 workflow 差异、验证器、三类成本对照、失败恢复说明。正常全局 GitHub 接受路径只构建一份静态网站；Vercel 构建另计。原有测试覆盖集合和分配语义不变，所有被分配项实际执行。

反例必须失败：旧 head/base、错 lock、缺文件、改一 byte、错环境、空测试列表、取消/未运行 shard、未知风险误跳过。运行已有 CI node tests、新增验证器 tests，再按现行门检查最终候选。本计划没有运行这些测试。

## 并行、停止与回退

A01 独占 workflow/工具版本写入；A02/A03 改 package 前协调。不更换 provider、ruleset、发布权限，不把科研服务器用作 CI。缺可靠身份验证或收益不足时停止推广。回退到原每分片构建路线，保留测量证据与全部测试。
