# 当前愿望的设计解释

这份文件只解释当前 BaseModel 愿望怎样推导成这个网站自己的信息架构和研究表达。科学事实、冻结实验结果、证据来源、chronology、模型数据和安全边界继续由现有科学/数据 authority 负责。

## L0 — 中心愿望

BaseModel 的核心不是“收集更多模型字段”，也不是“把实验结果做成网页”。它要帮助一个几乎没有上下文的人完成一条研究理解链：

```text
我在研究什么？
→ 为什么这个问题重要？
→ Base Model / 方法 / benchmark 分别是什么？
→ 我们具体做了什么？
→ 最基础的结果是什么？
→ 更复杂的诊断告诉了我什么？
→ 哪些结论有证据，哪些仍不知道？
→ 下一步该怎么研究？
```

如果页面包含很多正确事实，但读者仍然不知道这项研究为什么做、发生了什么、结果意味着什么，它就没有完成当前愿望。

## L1 — 真实读者会遇到什么情境

### 1. 第一次听到这条研究线

读者可能只知道 OpenEVO、SEED、WebShop、LoRA、GDR 中的一两个词。网站应先建立研究问题和对象之间的关系，而不是直接扔缩写、run ID 和复杂图。

### 2. 我需要向学长、同学或未来的自己讲这项实验

页面应该能形成一条自然叙事：为什么做 → 做了哪些实验 → 最基本结果 → 更深分析 → 目前能得出什么 → 还缺什么。不能要求讲述者重新从原始日志拼故事。

### 3. 我想真的复现或继续实验

这时需要从概念解释进入可执行 setup：模型身份、任务、预算、seed/协议、runtime、Passport、结果 owner 和验证方法都要能找到，但这些操作细节不应该抢占研究解释页第一屏。

### 4. 我想判断一个机制到底有没有价值

读者需要从直接分数开始，再逐层看到 loss、参数变化、Task Vector、谱/几何、输出长度、entropy、行为等诊断。复杂指标存在是为了回答研究问题，不是为了显得研究更复杂。

### 5. 我在选择或理解 Base Model

模型目录、模型详情、比较与 workbench 应帮助研究者理解模型替换会怎样影响可行性、可比性、复现和证据，而不是产生一个脱离任务语境的“最好模型”。

## L2 — 网站应该怎样回应

### 研究问题先于网站结构

首页和研究入口首先回答“我们现在在研究什么、为什么”，再把读者送往学习、运行、比较和结果。不要让读者先理解网站分类才能理解研究。

### 结果解释从简单走向复杂

实验分析页默认顺序应接近：

```text
做了哪些实验
→ 直接任务分数 / 成功率 / 后期平均 / 随轮次趋势
→ loss
→ 参数变化 / Task Vector
→ 谱、秩、几何
→ 输出长度 / entropy / 行为
→ 综合解释与局限
```

每个指标小节都应先回答“这个指标是什么、为什么现在看它”，然后给结果，最后才分析。

### 科研图表借鉴论文最终排版，整站保留网站身份

只有真正需要呈现科学证据的图、表或公式，才借鉴 ICLR/NeurIPS 最终 LaTeX PDF 的清晰度、三线表、刻度和图注。小型单曲线、单组置信区间、短表按单栏小图的尺度紧凑排版；多面板、复杂方法流程和多组效果对比可参考跨双栏图，在有空间的桌面上画大一些。网页正文仍按读者学习路径组织，手机需要适配；菜单、状态、交互工具和整站页面不套会议论文模板。具体宽度规范见 [UI design principles](../agents/current/ui-design-principles.md#research-figure-and-quantitative-table-width-borrow-the-paper-object-retain-the-website)。

### Setup 和 Analysis 分层

实验身份、任务流、预算、seed、evaluation boundary 必须明确，但不应该让读者在看到结果之前穿过一堵配置墙。第一层给理解研究所必需的 setup；完整命令、日志、运行细节放到更深层或执行手册。

### 复杂数学服务于理解

公式、推导、序列建模对应关系等应该存在，而且要严谨；但概览页只保留理解当前实验所需的最短推导。详细推导放到专门机制页。

### 科学边界必须和结论一样显眼

已完成实验、未运行实验、诊断证据、正式结论、历史结果和当前结果必须区分。不能为了页面“完整”补出未做的数据，也不能因为愿望希望故事更顺就改变实验 chronology。

## L3 — 主要页面与层级

### 首页 / 研究任务入口

角色：快速说明当前主要研究问题，以及学习、运行、比较、看结果分别去哪。它不是模型目录首页。

### 研究 Flow / 机制页

角色：让没有上下文的人建立 Base Model、SEED、OpenEVO、benchmark、更新对象和实验循环之间的关系。

### Study / Results 页面

角色：把一组已经有 authority 的实验变成可理解、可审计的研究叙事。先实验和基础指标，再复杂诊断；结论、边界和未做实验都要明确。

### OpenEVO 系列的三篇研究博客

用户确定三篇文章按 **方法 → 学长十问（研究问题） → 我们的回应实验** 顺序阅读：

1. 第一篇 `/research/seed-openevo/study/openevo-methods/`：详细讲 OpenEVO、BUNDLE、LoRA / SD-LoRA、普通参数更新、固定容量和历史 β，必要时展示数学公式、统一机制图、可展开的 rank8 技术解释。
2. 第二篇 `/research/seed-openevo/study/advisor-questions/`：独立呈现学长研究问题的背景、科学意义和问题之间的关系。历史会议原本有六个讨论方向，后来整理出 Q01–Q09，Q10 是会后独立复现；这篇不提前替问题作答，不重复结果图表。
3. 第三篇 `/research/seed-openevo/study/parameter-memory-results/`：我们的回应实验。按第二篇的 Q01–Q10 一一对应，列出真实实验、测量结果、证据边界及下一步；容量、β、方向与文字状态等复杂数据放在第三篇详细分析。

三篇共享一套源数据和原始记录，不为页面叙事重新发明结果。固定浅灰绿/白色阅读面仅作用于这三个博客，不要覆盖 BaseModel 其他研究工具页。每篇有可跳转目录、章节和相互链接；方法一篇详细，其他两篇按需引用。科研未知项不得靠文章结构隐藏。

### Reproduction / Run 页面

角色：执行优先。这里可以更具体地放环境、硬件、固定资产、命令、预期输出和失败分支。它不承担完整概念史。

### Model / Paper / Family / Compare / Workspace

角色：支撑研究决策。它们帮助理解候选、可比性、模型角色、证据和替换影响，而不是与当前研究 mission 平行成另一个互不相干的网站。

### 深层推导页

角色：承载详细机制、数学推导和技术背景。上层页面应给足上下文和链接，但不把深层推导全部复制过去。

## L4 — 注意力如何分配

BaseModel 面对的是注意力有限、可能没有上下文的技术读者。第一屏通常只应该有一个主要问题或结论中心。

设计拿不准时，优先问：

1. 一个第一次来的人能不能在很短时间内知道这页在研究什么？
2. 最重要的实验结果是否比高级诊断更早、更显眼？
3. 读者是否知道某个数字证明什么、又不证明什么？
4. 图表、公式和结构是否减少理解成本，而不是增加“研究感”？
5. 同一个实验跨页面的名字、setup、状态和结论是否一致？
6. 如果把所有视觉装饰去掉，页面的研究逻辑是否仍成立？

## L5 — 当前阶段的特化

当前 BaseModel 可以明显围绕 SEED × OpenEVO 特化，因为这是正在持续推进的真实研究任务。

特化应该体现在：当前研究 mission、实验入口、benchmark、机制、结果和资产更容易找到；而不是把整个产品的数据模型和长期结构硬编码成只支持这一组实验。

未来研究任务变化时，应能替换“当前 mission”，同时保留研究理解、复现、比较、证据和决策这套长期骨架。

## 不属于这份文件的内容

通用 UI/HTML/accessibility 规范、Vercel/CI/Git 操作、某次 PR 或页面事故、具体实验封存数字、当前模型 catalog 事实、实时 provider 状态都不属于愿望设计解释。它们继续由现有 current policy、测试、scientific authority 和 live evidence 负责。

### 学长十问的速读层与详细报告共享一个状态来源

第三篇向忙碌项目老师汇报时：

1. 首屏先表明十问中局部已有结论、关键问题待验证与核心验证未完成的数量及边界；不把这个数量冒充科研完成百分比。
2. 第二节为十问逐一提供“一句话回答 / 实际已做 / 还差什么”，标题能跳到对应详细证据。原来经过讨论、需要保护的文字保留在可展开的深度层，不强迫第一次阅读者全部消化。
3. 详细问答沿用同一个科学回答状态，开头说明当前阶段和剩余差距，再进入实验设置、数字、置信区间和证据来源；没有正式科研结论不得用绿色覆盖工程完成。
4. 状态只有绿色（有边界的局部结论）、黄色（做过实验而关键结论未确认）、红色（核心正式验证未完成）。普通的正文灰色不能冒充状态；颜色必须辅以明确文字，浅色/深色/手机显示都一致。
5. 检查不止于 DOM 有十个状态：还要检查渲染颜色、速览/细节同源、关键科学边界。没有无上下文读者验收时不得宣称“老师能看懂”已经得到证明。

以上是第三篇的阅读合同，不强迫第一篇方法介绍和第二篇纯研究问题页呈现实验状态，也不改变实验仓库的科学真相权威。
