**Phase A 冷读记录**：仅依据两张截图；未访问网页、代码或历史偏好材料。答案留存在本条消息中，不进入 Phase B。

**1｜5–10 秒内，这页讲什么？**  
这是一页研究方案说明：之前在 SD–LoRA 训练完成后决定“要不要采用”，现在想让学习事件直接控制 LoRA 参数怎样更新。第一感觉是“解释方法改版”，不是“展示实验成果”。

**2｜注意力首先落在哪里？**  
桌面版首先是巨大的 **“Gated–Delta SD–LoRA”**，其次是下面“我们之前做的……放错了层级”。手机版也是标题先被看到，但很快进入密集正文；标题告诉了方法名，却没有直接告诉研究进展。

**3｜最重要的一条事实、结果或下一步？**  
**第一版 D1 已冻结设计，但还没有开始正式实验。** 这是理解整页证据分量最重要的信息：目前展示的是设计与资格验证，不能据此认定比 Vanilla 更好。它应该出现在首屏。

**4｜最像机器写作或汇报腔的地方？为什么？**  
“**AdamW memory + LoRA factors 闭合了真实 write 与 State 位置**”。“闭合”没有交代具体解决了什么，中文句法里又塞入多组英文术语，像内部进度汇报压缩句。需要读者先解码，才能理解实际结论。

**5｜哪些术语迫使读者补上下文？**  
开头的 **GDR–v1、16 道题、learning event** 就要求补背景；随后还有 **factor State、causal update–local state、D0.22／D0.26、D1**。尤其 D0 编号和全大写步骤标签，看得到研究经过很多验证，却不知道各编号的含义与重要性。

**6｜是否有多个视觉中心争夺同等注意力？**  
首屏没有：大标题明显占主导。中后段的 **“推导怎样收敛到 factor State”**、**“现在的 State 直接放在 LoRA rank–8 factors 里”** 和底部冻结设计框，都以醒目的标题争夺“核心结论”位置。手机版逐段出现，更多是层级拉平，而非同时抢眼。

**7｜重要边界是否藏得太深，可能造成误读？**  
**是，主要是“尚未开始正式实验”。** 首屏有“D1 设计已冻结，尚未获执行授权”，但字号小、颜色淡；明确的大标题说明在很后面。此前“真实 write”“已闭合”等措辞容易让人把方法层面的验证理解成效果已经得到证实。边界并非缺失，而是出现得不够醒目。

**8｜会删掉、改名或下沉什么？**  
把“设计冻结、正式实验未启动”移到标题下；把“推导怎样收敛到 factor State”改为“为什么把更新放进 LoRA 参数”；把 D0 编号、全大写状态码和详细验证路径下沉到现有证据展开层。正文保留每一步“发现什么问题、因此改了什么”，不损失研究逻辑。

**9｜继续阅读意愿：1–5 分？**  
**3／5。** “之前把门控放错了位置”有吸引力，前后两张流程图也让改动显得具体。但读到中段，需要连续翻译术语和内部编号；等到最后才确认尚未正式实验，会觉得阅读顺序没有优先回答“现在到底证明了什么”。
