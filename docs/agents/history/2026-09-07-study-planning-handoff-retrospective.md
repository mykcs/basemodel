## 4. 科研概念：这是表述纠偏，不是新增实验结果

本对话没有检验 GDR 效果，也没有证明研究上限。以下是必须保持的推理边界：

- 系统级比较、起点差异分析、机制对照回答不同问题；首页需要解释它们的关系，不能用栏目相邻代替论证。
- 正式应用更新次数与候选训练次数不是同一个计数；未知次数不补猜测。
- 相同 rollout 数不自动意味着相同信息量或资源；具体差异需来自实验记录。
- No-GDR 的策略级结果不能单独解释某个被拒候选在原路径的反事实长期效果。
- 训练结束、最终测试完成、比较条件成立与结论可信，分别需要证据。
- 参数变化或行为变化本身不能证明稳定改善，更不能证明能力天花板。

这些边界属于已有研究诚信框架；新增加的是如何将其具体映射到 study 的问题、实验、摘要和入口，而非另起科学合同。

## 5. 重复犯错检查：旧规范为什么没挡住

| 已有规则 | 本次状态 | 缺失环节 | 本轮处理 |
| --- | --- | --- | --- |
| 完整解释只有一个主页面 | 用户仍报告嵌套重复；本轮未现场证实具体组件 | 规则没有被展示为逐块内容迁移和导入边界检查 | 在现有 journey owner 增加任务级检查，不再另造去重规范 |
| 可读性不能只凭测试数量 | 原方案仍强调压缩比例 | 代理指标容易代替读者判断 | 保留真人理解门槛；未测就标待验证 |
| 工具发现不算执行 | 本次实际输出了过大的注册表/树/长文，结果被截断 | 调用点缺少输出预算和完整阅读检查 | 在操作原则加入具体 preflight；本次后续树/PR输出采用筛选和定长片段 |
| 历史与当前权威分开 | 方案引用旧状态与旧 PR 存在失效风险 | 交接未必讲清固定文件与可变基线 | runbook 已注明需重新核验，操作原则补齐交接合同 |
| 记忆与仓库不同 | 用户再次要求实际记忆写入 | 能力不一定存在；措辞容易过报 | 仅报告真实写入数，不用推测补足 |

不把失败统一归咎于“文件太深”：根 AGENTS 已路由到 owner，部分问题是执行未落到动作、阅读被截断或测量代理不合适。继续增加长篇入口会加剧阅读成本。本轮只修改既有 owner 的增量、现有触发器与索引。

本次文档提交仅保护规则可发现性与交接清晰度；尚未加入网页组件/渲染回归，也不声称已防止所有未来重复。产品侧检查由方案实现 PR 落实。

## 6. 长期记忆候选与本轮实际结果

适合未来具备写能力时保留：

1. 用户希望面向没有智能体/项目背景的人，用中文讲清研究目的、阶段起止和结论边界。
2. 对重复出现的问题，用户要求实际修复共享根因并建立可核验交付，不接受只追加一份总结或改排版。
3. 用户重视可由新 Agent 独立执行的仓库方案和明确交接入口；具体 PR/路径不属于永久偏好。

本轮能力检查只发现个人上下文检索，没有账户长期记忆写入接口；实际写入 0 条。这里是候选清单，不是记忆回执。工具可用性只是本轮事实，未来重新发现能力。

## 7. 历史真实性与刻意不保存

不保存到长期规则：暂存文件绝对路径、当前 PR 是否开放、当前模型轮次/百分比、GPU 占用、PID、构建队列、临时账号能力、部署 share 参数。没有产生的服务器/GPU/Docker操作不补写；已有外部事故仅在其原案例保留。

方案 PR 的 SHA 用于复核当时内容，不作为将来执行基线。旧通用规则没有被标记过时，因为本次未证实它们失效；被修正的是“只整理首页即完成”“长度等于清晰”“一个概念不能在多页出现”等过强建议。通用原则与任务方案要读在各自作用域内。

## 8. 下一位 Agent 的最小 preflight

1. 确认这次是讨论、方案、实现还是发布任务，沿用已给授权。
2. 固定要阅读的方案版本，同时刷新实际仓库和重叠 PR；尚未合并的文件从 PR ref 读。
3. 检索现有 owner，不再创建平行标准；完整阅读所需段落，不能以截断输出代替。
4. 建立问题/实验/结论及逐块迁移表，标明事实来源与待验证项。
5. 先落实承接页，再删重复；共享数字单一来源，实验详情保持完整叙述。
6. 实现时检查实际导航、间接整页导入、可见比较限制及移动端。
7. 报告实现、自动验证、人工审查、真人理解和发布各自状态。

REPEAT-CORRECTION 使用证据：重复可读性/过量工具输出 → 当前 journey/操作原则 → 已对照基线 owner 与旧 reader-journey 案例，检查本次真实工具回执 → 仅允许原子提交本文档增量 → main/目标文件/重叠 PR 改变则重新核对。无需新增批准层。
