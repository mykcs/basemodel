## What happened

The first mechanism delivery contained correct SD-LoRA facts, a reusable 16:9 canvas, numbered steps, and local arrows. It was nevertheless possible to read the surface as a row of summaries rather than a process that visibly moves through a main path, side inputs, state admission, and a return to the next round. The task was reported complete before that explicit visual requirement had its own artifact-level acceptance check.

The owner then corrected the same failure class directly: there was no convincing HTML flow, and the direction of movement was not visible enough. This was not a missing style preference. Current BaseModel authority already said that a branch/loop/dependency should be expressed as real structure and that a group of cards is not automatically a visualization.

Therefore the recurrence is classified as a **use-site enforcement failure**: the rule existed, but the implementation/review path did not turn the named deliverable (“HTML flow”) into a topology-specific witness and rendered test.

## Durable changes chosen by this closeout

1. `human-thinking-web-expression-contract.md` gains a compact topology witness for non-linear flows: main path, side branch/input, return or terminal, connector carrier, and rendered acceptance. A simple linear procedure may still remain an ordered list.
2. `ui-change-visual-acceptance-gate.md` gains a failure scenario for “all nodes exist, but the flow is not visually recoverable.” Its falsification must inspect real connector/return structure or rendered directional geometry instead of only text presence.
3. `src/lib/humanThinkingWebExpressionContract.test.ts` protects those two governance requirements so this closeout does not depend on future Agents remembering prose.

No new parallel style guide or second HPL policy is created. The preference itself was already present in current authority; the missing piece was activation and acceptance at the use site.

## Temporary state intentionally excluded

This closeout does not promote current PIDs, local ports, worktree paths, temporary screenshot/crop locations, feature-branch heads, pending browser progress, Preview URLs, deployment IDs, or live PR/provider state into standing policy. Those observations matter only to the execution that produced them.

The separate SD-LoRA feature branch remains a separate development artifact. This closeout neither declares that feature merged nor uses closeout self-merge authority to merge it.

## Future-Agent test

A new Agent starting from root `AGENTS.md` should reach the human-thinking expression contract for any process/diagram task. If the requested semantic object has a branch, loop, dependency, or explicit diagram requirement, the Agent should now be forced to answer “what are the edges and how will I prove they render?” before calling a row of cards a flow. The UI gate should then require evidence of that topology on the rendered surface.

If a future Agent can still pass review by checking only node text or card count while the return edge/branch is visually absent, this closeout has failed.
