## 原始反馈（不要抹平成「优化 UI」）

- 「Q02 SFT 跟 OPSD 有我们之前商量并修改过的版本，网页为什么又随意生成另一个？」
- 「Q06 在对话中的决策图比网页还好」——它不是要求重新发明一张图，而是要求保留选择过的版式。
- 「仅修 Q02 一图花了 34 分钟」，用户接下来要从 Q01 查到 Q10，修复机制需要可复用、可快速定位。

主要失败模式：对话中批准过的图形决策没有变成可执行的版本约束；后续自动重排只看组件存在、文字大致正确，可能把已批准的两路线、三选一或分叉关系换成通用卡片。发生偏差时，逐题复跑整个网页矩阵又延长了反馈环。

## 快速复用与严谨边界

每修一题，先跑 `npx playwright test tests/e2e/advisor-intelligence-q02-q10.spec.ts --project=chromium --grep 'Focused QNN'`；别为了修一题而先做十题统一重绘。确定候选后再跑全视口/双主题/Chromium+WebKit 与 `npm run preflight:ui`，最后看精确 HEAD 的 Vercel Preview 和 Production。不要只传 PR，让用户必须亲自发现错位。

2026-10-23 的独立 macOS 临时副本：静态生产构建 PASS；十题 Chromium 10/10，约 9.4 秒；两个浏览器的 Q01–Q10 专项、全视口概念检查及 Q04 图形矩阵共 54/54 PASS，约 31.4 秒。该测试证明结构、交互和指定几何；**不等于已逐像素比对原对话中的全部截图，也不等于作者已批准每题的最终审美**。用户后续的逐题意见仍优先于通用组件美学。初始 Linux 运行器因缺浏览器且 CDN 无法下载而失败，这是测试环境问题，使用已授权 Mac 隔离副本解决，未放宽断言。
