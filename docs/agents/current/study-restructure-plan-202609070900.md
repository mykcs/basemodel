## 1. 目标与范围

目标：使未参与实验的老师或同学能够理解研究问题、各实验的关系、证据支持的结论及其边界，并能找到下一步需要的资料。

此次同时处理四层问题：研究逻辑、页面归属、文字叙述、呈现与维护机制。不能只删除首页组件、统一卡片样式或将旧文章整体搬到子页后宣布完成。

实施范围包括：研究总览、设计、运行与复现、能力与机制、结果、关联实验详情；重复导航与旧锚点兼容；共享事实来源；必要的结构检查和浏览器验收。

不借网站重构改变实验配置、运行权限、训练任务或科学合同。新科学疑问登记为待解决问题；重写措辞不能代替实验验证。当前只交付本方案；后续实施需有对应授权。

保存目标提交、访问时间、桌面和手机截图、路由清单、页面标题树、可见导航、正文字符数及直接导入组件。页面抓取失败时继续检查源码与可用预览，并将未验证项标为未完成，不能复述旧描述充当线上验收。

对 study/ 每个实质内容块建立迁移记录：

| 字段 | 要求 |
| --- | --- |
| 来源 | 路由、标题/锚点、组件或内容文件 |
| 回答的问题 | 用一句读者能懂的话说明 |

## 3. 先建立研究问题与实验关系

为每个研究问题设置稳定 ID，至少区分：

| ID | 研究问题 | 需要的证据 | 不能越过的边界 |
| --- | --- | --- | --- |
| Q1 | 在明确约定的资源与评估条件下，OpenEVO 整套系统表现如何？ | 配置、预算差异、最终评估及比较资格 | 一次运行不能证明能力上限；系统差异不能归因于单个机制 |
| Q2 | 为什么不同起始经验与模型会出现不同训练表现？ | 起点质量、行为轨迹、后续表现及必要对照 | 跨模型差异或相关性不能单独证明因果 |
| Q3 | GDR 等持续学习机制如何影响结果？ | 明确干预、基线、控制条件、预算记录和评估 | 取消筛选的整体效果不等于某次被拒更新的长期效果 |

为每项实际实验登记：实验 ID、主问题 ID、辅助问题、基线、改变项、固定项、数据与模型起点、预算口径、评估协议、执行状态、证据成熟度、当前结论、限制、来源、详情页。

首页只展示与当前主问题最相关的少量实验。历史 7B、当前模型实验和机制对照必须标明角色，不能混成一个全局进度。

交付门槛：所有首页实验和结论都能追溯到问题 ID；没有明确回答对象的内容先归档或补足关系，不凭篇幅强行保留。

## 4. 页面职责与内容归属

保留现有可用 URL；下表的“实验详情”是页面类型，不要求新增一套目录。优先整合现有实验页，确认确有缺口才新增。

| 页面 | 必须回答 | 应包含 | 不应承担 |
| --- | --- | --- | --- |
| study/ 总览 | 研究什么、为何重要、现在如何、知道什么、去哪深入 | 简要背景、问题关系、实验状态、少量结论和下一问题 | 完整设计教程、运行手册、证据仓库 |
| Design | 为什么这样比较，什么条件下比较有效 | 系统比较/机制对照、预算、数据划分、指标、设计决策 | 当前轮次和原始日志 |
| Run | 如何运行和复现，如何确认用的是正确实验 | 身份、环境、命令、产物、来源与状态核验方法 | 全套研究背景和重复结果叙述 |
| Capability | 哪些机制与行为问题值得解释 | 机制问题索引、跨实验综合、证据限制 | 每个实验完整结果的第二份副本 |
| Results | 有哪些可比较的结果 | 评估条件、结果表、学习曲线、比较限制 | 把训练中分数包装成最终排名 |
| 实验详情 | 为什么做、改了什么、结果如何、意味着什么 | 一项实验的完整叙述，链接共享方法与证据 | 大段复制通用设计和运行手册 |

具体迁移规则：

| 现有主题 | 主要归属 | 首页保留 |
| --- | --- | --- |
| 训练设计实验室、责任边界、实验路线 | Design | 一句设计原则和明确链接 |
| Fair Comparison、rollout/update/epoch、150/160、教师预算、测试泄漏 | Design 对应概念章节 | 影响首页比较的必要限制 |
| parser、checkpoint、运行 gate 的检查方法 | Run | 只有会改变结论资格的状态摘要 |
| gate 的科学理由 | Design | 必要的解释链接 |
| GDR 接纳/拒绝与 No-GDR 对照 | 对应实验详情；Capability 做索引 | 观察、未知点、下一问题 |
| 实时轮次、训练进度 | 共享状态来源，由总览与运行/结果页投影 | 时间与运行身份明确的摘要 |
| 历史事故和失效设计 | 有日期的决策记录，关联 Design/Run | 仅当它解释当前选择时引用一句 |

## 5. 总览页面的具体结构

首版正文预算为约 1,000–1,500 个中文字符，不含全站导航、表中数字和展开的原始证据。此预算用于约束叙述，最终以理解测试为准；关键比较限制不因字数被删。减少 60–80% 只是与基线比较的观察指标，不是单独通过条件。

### 5.1 第一屏：研究问题与最低背景

唯一 H1：OpenEVO × SEED：WebShop 研究。

先解释 WebShop：让模型按照购物要求，在模拟商店中搜索并选择商品。随后解释本研究为何关注训练：考察系统能否利用经验改善完成任务的能力。

主问题建议文案：在明确约定的训练资源与测试条件下，OpenEVO 能把基础模型的任务表现提升到什么程度？

下一句连接子问题：我们同时检查起始经验和更新机制，解释它在哪些条件下有效、为何失败。

首屏不出现内部 campaign 名、SHA、未经解释的阶段编号。给出简短流程：准备起始经验 → 持续训练 → 固定规则评估；下方说明不同实验处于不同位置。

### 5.2 当前进展：按实验展示

首页第一张数据表保留用户关心的 OpenEVO 分数与 SEED 分数，但每项分数必须就地标注阶段和口径。

建议列：实验/模型、执行状态、OpenEVO 分数及评估阶段、SEED 最终分数及协议引用、尚缺步骤。移动端按实验转为带完整字段名的纵向记录。

如果只有训练分：标注“训练过程分数，不能据此计算最终胜负”。如果没有核验到分数：显示“暂无已核验结果”，不补零、不沿用旧数据。

状态至少包含 observed_at、实验身份、来源。刷新频率和失效阈值沿用已有数据合同；若无合同，先确定采集频率再设置阈值。页面显示“截至某时的记录”；超阈值标“状态未更新”，不能继续声称“正在正常训练”。

### 5.3 当前认识：最多三项

每项包含：一句观察、它支持什么、仍不能说明什么、证据链接。结论标题必须标明“已观察”“当前解释”或“待验证”。没有可靠结论时可以少于三项，不能用常识凑数。

### 5.4 下一道问题：解释研究为何继续

放在发现之后，使下一实验由现有证据自然引出。最多突出一个主要问题；若 GDR 对照仍是当前重点，解释“候选更新经过训练后还要被决定是否应用”，再说明为什么需要对照。不要提前断言 GDR 有害。

### 5.5 深入入口：按读者问题命名

四个入口分别写成“为什么这样比较”“怎样运行与复现”“为什么有效或失败”“最终结果怎样”。每个入口一句说明和一个具体链接，不再展开第二篇正文。相关实验入口可放在对应发现和下一问题旁。

## 6. 实验详情页的固定叙述合同

按以下顺序展开，目录只属于该页：

1. 为什么做：前一项观察留下了什么未知。
2. 如何回答：比较对象、改变项、固定项、起点、预算和评估。
3. 执行到了哪里：有时间和身份的事实；与证据成熟度分开。
4. 看到了什么：数字、图表、样本范围及适用条件。
5. 如何解释：支持的结论、替代解释、不能推断的事项。
6. 下一步与复现：尚缺证据、相关实验、运行说明、详细来源。

GDR 示例：观察候选更新被拒绝 → 提问筛选策略的整体作用 → 定义保留与移除筛选的比较 → 记录训练、候选与应用次数及实际资源 → 按预定协议评估 → 区分策略效果与单次更新的因果解释。

如果改变筛选同时改变训练路径、调用次数或实际预算，必须记录差异并限制结论；不能通过文案写“公平”消除实际差异。

## 7. 文字标准与正反例

每段只推进一个问题。开头先说读者关心的事情，再给必要术语。术语首次出现时就地解释；概念总解释页只作为继续阅读入口，不能要求读者先查词典。

章节之间必须有明确逻辑：例如“前面的结果还不能判断筛选是否有帮助，因此下面介绍对照设计”，而不是突然出现另一个 01–08 目录。

| 不合格 | 合格写法 |
| --- | --- |
| Stage2 R87 reconciliation 已完成 | 截至〔核验时间〕，此实验完成〔轮次〕轮训练；最终测试〔状态〕。内部核对记录放入证据区。 |
| 只训练了 7 次 SD-LoRA | 正式应用了 7 次更新；生成候选更新的训练次数需另行统计。数字必须绑定具体实验。 |
| GDR 错误拒绝了长期有益更新 | 观察到一些候选更新被拒绝；它们是否长期有益，现有证据尚不能确定。 |
| OpenEVO 49，SEED 89，因此落后 40 | 先标明两项分数的任务集、评估阶段和统计口径；资格不一致时不计算胜负差。 |
| 已完成 | 训练已结束；最终测试仍待完成。或者：最终测试已完成，比较条件尚待核对。 |
| 同样 1,440 条，所以信息量相同 | 轨迹数量相同；成功率、长度、教师信息与实际资源可能不同，需分别记录。 |

全文禁止用“完整闭环”“已对齐”“通过 gate”等词代替具体事实。每个阶段说明何时开始、什么条件算结束。模型、阶段、轮次首次出现必须有对象，不能让读者猜主语。

重要限制必须在结论或图表附近可见；不能将训练分/最终分差异、预算差异、单次运行限制只藏在折叠区。折叠区用于原始日志、完整参数、SHA 和校验细节。

## 8. 导航、视觉和交互标准

全站导航使用既有结构，仅修复本研究范围涉及的重复输出；不能借本任务重构无关全站导航。

研究导航统一为总览、设计、运行、机制、结果；当前页明确高亮。长详情页可有页内目录，但不与两套顶部导航同时常驻。首页不需要另一套复杂目录。

每页一个 H1；标题按 H2/H3 推进，无重新开始的整篇文章。最多一层有边框的内容容器，避免卡片内再套多层卡片；这不限制有语义必要的普通列表。

首屏解决研究对象与目的；后续用留白、标题和必要的比较表建立层级，不依赖大面积装饰。图仅用于解释流程、对照或数据关系。状态不得仅靠颜色表示。

桌面验证 1440×900，手机验证 390×844，窄屏验证 320px；检查 200% 缩放。无整页横向溢出；必要宽表可局部滚动且有提示。键盘能访问全部链接和展开项，焦点可见，文字对比达到 WCAG AA。尊重减少动画设置；关键结论不靠悬停和动画才能看到。

移动端菜单在关闭时不能留下重复可聚焦导航；桌面/移动分别生成的导航须检查实际可见与辅助技术行为，不能只凭源码字符串出现两遍判错。

## 9. 内容与组件实现约束

沿用仓库现有 Astro/内容集合/数据结构；实施前核验，以下是职责建议而非已确认的文件结构。

共享记录最少包括：ResearchQuestion、Experiment、Claim、Metric、EvidenceReference。用稳定 ID 建立引用，无需为此次重构引入数据库或新 CMS。

Metric 需包含数值、单位/尺度、任务集、评估阶段、样本范围、实验身份、时间和来源。执行状态与证据成熟度使用不同字段，展示也分开。Claim 需包含类型、适用范围、证据引用、限制和更新时间。

总览消费短摘要与共享数据，不导入整页设计/公平性组件。共享 Layout 只负责布局、导航与通用外壳，不隐藏注入大型正文。审查直接及间接导入，避免把整篇内容改名后绕过检查。

页面可分别解释同一概念，但不各自维护相同事实和完整通用定义。结果修改从权威记录更新；历史记录保留原时间，不被当前状态覆盖。动态运行记录不得成为实验执行授权。

新增内容必须回答：属于哪个研究问题、主解释在哪、是否已有事实来源、是补充还是修正旧结论、其他入口如何更新。不能默认添加到首页。

| C 承接内容 | 先完善目标子页、来源和旧锚点映射 | 可访问的承接页面与证据链接 | 独有内容未丢失 |
| D 总览重构 | 移除嵌入正文，接入摘要与共享状态，整理导航 | 总览预览、桌面/手机截图 | 标题与导航清晰，状态口径准确 |
| E 防复发 | 接入已有内容标准与轻量检查 | 规则变更、检查脚本、针对性回归 | 能识别整页嵌套、失效引用等真实风险 |
| F 验收 | 浏览器、科学语义与新人理解检查 | 验收记录、缺陷修复、前后对比 | 必过项全部通过或明确未完成 |

阶段顺序是工作门槛，不要求每阶段都向用户索取确认。后续获得实施授权后，日常可逆工作连续推进；生产发布按当时已有授权执行。本方案本身不授权部署。

在独立分支实施，保留用户与其他工作者的修改。PR 数量按可独立审查的边界决定，不为拆阶段反复触发全量 CI。发布前保留旧提交与可回退部署记录；旧路径变化有明确重定向，旧 hash 锚点使用页面内兼容锚点或专门映射，不能假设服务端可读取 URL fragment。

## 11. 可执行验收矩阵

全部“必过”项不采用平均分抵消。CI 通过只覆盖自动检查，不能等同全部验收完成。

| ID | 标准 | 方法与通过条件 |
| --- | --- | --- |
| IA-01 必过 | 总览只有一条叙述主线 | 人工检查五个区块；无整篇设计/公平性二次目录 |
| IA-02 必过 | 每页职责明确 | 迁移清单覆盖原首页全部实质内容块，去向可访问 |
| IA-03 必过 | 无重复可见导航与整页嵌套 | 桌面/手机实际渲染检查；间接组件依赖检查 |
| SC-01 必过 | 首页结论可追溯 | 100% 实质结论有实验、证据和范围；未知明确标注 |
| SC-02 必过 | 分数口径就地可见 | 100% 分数有评估阶段/尺度与协议引用；不合格比较无胜负差 |
| SC-03 必过 | 执行与科学完成分开 | 每项首页实验列出仍缺的评估或证据步骤 |
| SC-04 必过 | 无过度归因 | GDR、模型差异、上限等叙述逐项审阅；假设不写成结果 |
| DT-01 必过 | 当前状态可核验 | 有时间、身份与来源；失效和缺失有明确显示 |
| DT-02 必过 | 事实无多份手写漂移 | 抽查全部首页数字及跨页共享事实，来自同一权威记录 |
| WR-01 必过 | 文字自足 | 首页术语首次解释；段落主语清楚；阶段起止与转折明确 |
| UX-01 必过 | 深入路径可预测 | 从首页到设计、复现、最终结果、GDR 详情均不超过两次有效点击 |
| UX-02 必过 | 移动与键盘可用 | 指定视口、缩放与键盘检查通过；无关键内容截断或焦点陷阱 |
| LK-01 必过 | 无内容与链接损失 | 内链检查通过；已收集旧深链与锚点有承接；独有证据完整 |
| RG-01 必过 | 无功能回归 | 仓库要求的构建与受影响页面检查通过，相关浏览器测试通过 |
| RD-01 人工门槛 | 新人能正确理解 | 按下节方法测试；未实际找读者测试时只能标待验证 |
| SZ-01 参考 | 长度收敛 | 报告前后字符数与截图；约定预算超出时说明必要原因 |

自动检查优先加入已有轻量 CI：数据引用/必填字段、内链、标题结构、总览页面级组件边界。浏览器覆盖本次受影响路线，复用仓库要求的 gate。不要靠不断加全站截图或重复完整构建维持规则。

## 12. 新人理解测试

选择 3 位未参与实验、至少 2 位无智能体研究背景的读者。先只看首页 3 分钟，不提供口头补充，再分别回答：

1. 系统在做什么任务？为什么要做这些训练实验？
2. 主比较和机制实验分别回答什么？
3. 当前哪些工作完成、哪些仍未完成？
4. 目前一项有依据的认识是什么？还有什么不能判断？
5. 你会去哪看最终结果、GDR 原因和复现方法？

每题按 0/1/2 评分：错误或无法回答、部分正确、关键关系正确。每位至少 8/10；第 4 题必须 2 分。任何读者将不同评估阶段理解为可直接比较、把假设当成已证因果，均触发对应文案修复后复测。

查找任务每项目标为 30 秒内、最多两次点击；记录走错的入口，不只记录是否最终找到。

没有可用真人时，执行者完成同样问题的启发式审查并交付记录，标“预览完成，新人理解待验证”。不能让 AI 自答冒充真人通过，也不能因此停止其余可完成工作。

## 13. 最终交付包与完成定义

最终实施交付应包括：

1. 实际改动分支/PR、提交和预览地址；发布时另附线上地址与发布版本。
2. 基线与重构后截图，覆盖桌面和手机。
3. 研究问题—实验—结论—页面关系表。
4. 原内容逐项迁移清单及旧链接兼容清单。
5. 已落实的文字与页面维护标准，链接唯一主标准。
6. 验收矩阵的通过/失败/待验证记录及对应证据。
7. 明确的残留问题、回退方式和部署状态。

完成状态分开报告：方案完成、预览实现完成、自动与人工审查完成、新人理解验证完成、线上发布完成。不能将其中一个称为全部完成。

最终接受标准：读者能沿“为什么研究—怎样回答—观察到什么—如何解释—还缺什么”理解项目；总览能独立读懂，各实验能完整讲清，事实与证据可追溯，后续新增内容有明确去处。
